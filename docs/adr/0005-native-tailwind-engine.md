# 0005. Native Tailwind engine: Uniwind

- **Status:** Proposed. Accepted once the device tests below pass.
- **Date:** 2026-11-19

## Context

Unison's own components never depend on a Tailwind runtime: `defineStyles` compiles to layered CSS
on web and runs through Unison's own resolver on native (phase 2). App code should still be able
to use Tailwind classes on both platforms, reading the same compiled token theme. On native that
needs a Tailwind engine for React Native. The roadmap names Uniwind, with NativeWind as the
fallback, to be settled by a time-boxed spike (phase 0, step 17.5).

## Decision

Use **Uniwind** for `className` in native app code. Native apps import
`@unison-ui/tokens/native-theme.css` (not `theme.css`) in their `global.css`.

Spike results (Uniwind 1.14.0, Tailwind 4.3.5, Expo SDK 58 / React Native 0.88.1):

| Test | Result |
| --- | --- |
| 1. `bg-accent` renders the accent colour | With `theme.css`: **fails**. Uniwind keeps the `var(--unison-…)` chain, and nothing defines those variables on native (`tokens.css` is web-only), so the colour resolves to `undefined`. With the new `native-theme.css` (literal values, Uniwind's `@layer theme` / `@variant light` / `@variant dark` syntax): **passes at bundle level**. The bundle holds per-theme literal colours, `--spacing: 4` (`size-24` = 96) and `--radius-md: 8`. Not yet seen on a device. |
| 2. FlatList of 200 `className` rows vs `StyleSheet`, no visible jank | **Not run yet**: needs the Android emulator and the Perf Monitor |
| 3. System dark mode updates `bg-surface` without a reload | **Bundle level only**: the dark scope holds `--color-surface: #111113`, and Uniwind's default `system` theme follows the device. Not yet seen on a device. |

The spike ran in a Linux container without simulators. To finish it:

1. On the iOS Simulator and the Android emulator, run Tests 1–3 (CONTRIBUTING.md has the devices).
2. Record the Test 2 frame rates here.
3. If all three pass, set the status to Accepted. If one fails and can't be fixed within half a
   day, repeat the tests with NativeWind 4.x and record the outcome here.

## Alternatives considered

- **NativeWind:** the fallback. A mature ecosystem, but it is the engine Uniwind was built to
  outperform. It's only chosen if Uniwind fails the spike.
- **No native Tailwind:** app code would use `style` props only. That's simpler, but it breaks the
  concept's promise that Tailwind is first-class on both platforms.

## Consequences

- The token compiler has a third output, `dist/native/theme.css`, generated from the same token
  source as `theme.css`, so web and native Tailwind classes can't drift.
- Native apps need `withUniwindConfig` as the outermost Metro wrapper, and third-party components
  must be wrapped with `withUniwind` to accept `className`.
- `src/uniwind-types.d.ts` is generated by Uniwind (it runs with Metro) and committed so typecheck
  works on a fresh clone. Biome doesn't format it.
